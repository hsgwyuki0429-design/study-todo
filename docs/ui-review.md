# 添付デザインに基づくUI更新

対象: main `e162985`。ビルド不要の静的PWAと既存のES Modulesを維持。

## 実装範囲

- `styles.css`: 添付画像から16pxの左右余白、72pxの見出し領域、63pxの記録行、66pxの設定行、白い12px角丸グループ、青い操作色を定義。固定タイマー、一覧、評価、日別詳細、設定内フォーム、インポートダイアログに適用。
- `src/home.js`: 「ホーム」見出しと、表示状態をCSSで扱うための`data-mode`のみ追加。イベント・状態遷移・計測処理を変更しない。
- `src/app.js`: 4タブの装飾文字をインラインSVGへ変更。読み上げラベルと既存クリック処理を維持。追加の通信・画像依存なし。
- `sw.js`: キャッシュをv8へ更新。既存の`day-model.js`を初回シェルキャッシュに追加。
- `test/pwa-shell.test.mjs`: シェル内のES Moduleが参照するローカル依存をすべてキャッシュしていることを検証。

IndexedDBのスキーマ、問題マスタ593問、学習記録、予定、目標、チャレンジ、Cloudflare同期、MCP、日付判定、タイマー復元のコードに変更なし。READMEの591問という説明より、実データを優先した。

## 画面比較の反復

390×844 CSS px、Windows Chrome、Asia/Tokyoで撮影。添付画像を390×844へ縮小して比較した。写真にはOS表示領域があるため、比較撮影では上26px、下34pxを検証用スタイルで確保した。アプリ本体は`env(safe-area-inset-top/bottom)`を使用し、偽の時計やホームインジケーターは描いていない。タスクや赤い3マスは独立したテスト用IndexedDBのデータである。

| 回 | 観察 | 修正 |
|---|---|---|
| 1 | グループ開始y=104、開始ボタンy≈215、記録行が約66px | 見出し領域78→72px、タイマー余白縮小、記録行63pxへ |
| 2 | グループ開始y=98、開始ボタンy=200に改善。数字が太い。スケジュールの最上段が大きく欠ける | 数字のフォントを調整。日付行の行高とスクロール位置のCSS基準を修正 |
| 3 | スケジュールの9/9〜9/19が見える。数字の幅とフォームの質感に差 | 数字68px、行の余白微調整、ボタンの白文字コントラスト改善 |
| 最終 | 主要6画面、4タブのダーク表示、320pxと390pxの両テーマを再撮影 | 最終コードでブラウザー検証54項目を再実行 |

最終値: 記録・設定のグループ開始y=98、左右16px、ホーム開始ボタンy=200、高さ52px、集計カードy=268、ホーム下部カード終端y=731。写真の対応位置は約98、16、202、52、270、733px。

## 残る差異・検証範囲

- iOS実機／Safariでの検証は未実施。Windowsの代替フォントと自作SVGのため、Appleの文字・アイコンの輪郭までピクセル単位では一致しない。
- 画像よりセグメントを約8px高くして44px以上のタップ領域を確保。下部カード開始位置に約6pxの差がある。
- スケジュールは既存の今日中央表示と可変行高を維持。写真に写った位置とは今日の行が約14pxずれる。表示内容や件数は省略していない。
- 文字コントラストを優先し、一部の灰色文字と青い文字・ボタンは写真より濃い。
- 写真がない評価入力・日別詳細・ダークモードは、4枚から抽出した共通トークンで統一した。
- Cloudflare本番アカウントへの実同期は未実施。同期・MCPの既存自動テストは成功し、関連ロジックに変更なし。
