# 青チャート学習管理アプリ

青チャートの学習を記録・管理するスマートフォン向け PWA。勉強中にノートの隣にスマホを開いておく「伴走アプリ」として使う。

## 使い方

ビルド不要。静的ファイルをそのまま配信すれば動く。

```sh
python3 -m http.server 8000
# → http://localhost:8000/ をスマホのブラウザで開き、ホーム画面に追加
```

初回起動時に `data/questions.json`（青チャート数学I+A の問題マスタ 591問）が投入される（`src/seed.js`）。

## タブ構成

## 予定と実績の考え方

3つを区別している。

| ことば | 何か | 識別子 |
|---|---|---|
| 問題 | 例題50 のような、問題マスタ上の対象 | `question.id` |
| 予定項目 | 「その問題に今回取り組む」1件の予定 | `item.itemId` |
| 学習記録 | 「実際に今回取り組んだ」1件の結果 | `record.id` |

**1回の取り組み＝1件の学習記録**。同じ例題を2周目に解いても、同じ日に2回解いても、
記録は上書きされずに増える。逆に、やらなかった予定を別の日へ繰り越しても、
取り組み回数は増えない（学習記録には手を触れないため）。

学習記録の `planItemId` で「どの予定に対する取り組みだったか」を追える。
この仕組みより前の記録には入っていないので、「以前の形式の記録」として扱い、
同じ問題・同じ日というだけで対応付けを作ることはしない。

## スケジュールタブ

日付がずっと続く1本の並び。上へスクロールすれば過去、下へ行けば先の予定が出てくる
（端に近づくと自動で日を足す）。**タブを押すと、今日がちょうど画面の真ん中に来る**。
見出し（「今日」に戻るボタンと ⓘ）は上に貼り付いたまま、月が変わるところには月の見出しが入る。

1日は「例題」と「エクササイズ」の2段で、中身は正方形のマスだけで表す。

- **過ぎた日** … その日に実際に取り組んだ記録（予定に無かったものも出す）
- **今日** … 今日の実績 ＋ まだ残っている予定（日付の下に「45/60分」のように時間も出る）
- **これからの日** … その日にやる予定

マスは1回の取り組み（またはその予定）で1つ。**文字は入れず色だけ**で、すき間なく並べる
（同じ色が続いても数えられるよう、内側に細い境目だけ入れている）。実績は塗りつぶし、
未実施の予定は枠だけ。評価が入っていない実績は正解扱いにせず灰色にする。
チャレンジもまとめて1マスにはせず、**解いた問題の数だけ**マスを並べる
（チャレンジはたいていエクササイズなので、エクササイズの段に入る）。
マスが多い日は折り返して行が伸びる（件数は省かない）。

色の意味は、右上の **ⓘ** と、設定タブのいちばん下の「ヘルプ（マスの見方）」で見られる。
マスには読み上げ用のラベル（問題名・評価・所要時間）も付けてある。

日付を押すと、その日の詳細（実施した問題・チャレンジの中身・残っている予定・
繰り越しの履歴）へ移る。戻ると押す前の位置に帰る。過ぎた日に残っている予定は、
ここから理由をひとつ選んで別の日へ繰り越せる。

## 目標と計画

目標は「何を・いつまでに・どの状態まで」を持つ。

- **何を** … 対象の問題ID一覧。設定画面で章・単元を選ぶと、そのときの問題が対象として確定する
  （あとで問題マスタが変わっても対象は動かない）
- **いつまでに** … 期限（なしも可）と優先順位
- **どの状態まで** … 「取り組む」（1回ずつ解けば達成。✕でも取り組みとして数える）か、
  「習得する」（その目標に結び付いた**最新**の取り組みが ◯完璧にできた であれば達成）

達成として数えるのは、その目標に結び付いた予定から実施された取り組みだけ。
2周目の目標を作っても、1周目の記録では達成にならない。

**学習に使える時間**は、曜日ごとの標準・日付ごとの上書き（0分の日も可）・「今日はあと○分」・
予備時間で決める。未設定と0分は別物として扱い、未設定の日には時間があるとみなさない。
スケジュールの各日には「予定○分／使える○分」が出る。

**所要時間の見積もり**は、本人の実績（同じ問題の近い条件 → 似た問題）→ 保存された仮見積もり →
種類と難易度の既定値、の順に決まる。初見と復習、通常とチャレンジは分けて扱い、
計測忘れ・中断・制限時間切れの記録は計算から外す（記録そのものは消さない）。
タイマーは「問題を始めてから評価を記録するまで」なので、答え合わせの時間は既定で含む扱いにしてある。

日々の配分は Claude に頼む（`docs/mcp.md` の「目標と再計画」）。
アプリ側は数えること（実績・残量・見積もり・時間の過不足）と、安全に保存することを受け持つ。

## ホーム画面

上半分＝タイマー（固定）、下半分＝可変エリア。学習中に画面遷移は行わない。

**タイマーは二段表示**。左上に小さく「学習時間」（セッション全体。問題を切り替えても止まらない）、中央に大きく現在の問題の累積時間。

下半分は4状態を切り替わる。

1. **待機** — 今日の累計時間 ＋「学習を開始」。「やること / やったこと」の切り替え
2. **タスクリスト** — 例題を1問ずつ展開。チャレンジは1行として混在
3. **記録入力** — 5択を1タップで記録
4. **チャレンジ** — 制限時間付き。全体タイマーと問題ごとの累積ストップウォッチが並行して動く

待機画面の「やること」では、タスクごとに **「固定」** を付け外しできる。固定したタスクは
AIから変更・削除・別の日への移動ができなくなる（外せるのはこの画面からだけ）。
学習を始めると、いま解いているタスクをクラウドへ知らせ、AIが動かさないようにする
（オフラインのときは知らせが届かないため、その保護は効かない。詳細は `docs/mcp.md`）。

完了したかどうかは**予定項目ごと**に見る。同じ例題を1日に2回やる予定なら、
1回目を記録しても2回目は残る。

記録した問題は**リストから消える**。記録後に次の問題が自動で始まることはなく、**やりたい問題を自分でタップしたときに計測が始まる**（順番通りに進むことを強制しない）。

## チャレンジ

問題をタップして切り替えても**評価は聞かれない**。元の問題は一時停止するだけで、戻れば続きから加算される。何度行き来してもよい。

問題リストの一番下にある「終了」を押すと、**そこで初めて全問の評価入力**に移る。対象の各問題について5択を順に入力し、入力が終わった時点で結果（制限時間内に終えられたか・各問のラップタイム・各問の評価）が保存される。

## 記録タブ

章 → 単元 → 例題とたどり、その例題の取り組み履歴を見る。取り組み1回につき正方形のマスを1つ、
古い順に並べる（同じ日の2回分もまとめない）。マスを押すと、その回の日時・評価・所要時間・
通常かチャレンジかが出る。マスの見た目（色だけ・すき間なし）はスケジュール画面と共通。

時系列の一覧は置いていない。「いつ何をやったか」はスケジュールの過ぎた日で分かるので、
ここが受け持つのは「この問題を、これまで何回、どうだったか」だけ。
章ごとの進捗パーセンテージは表示しない。

## スケジュールタブ

上半分がカレンダー（月 / 週 / 年、矢印で前後に移動）、下半分がその期間の進捗バー。

**カレンダーのマス**は日ごとの達成率を表す。表示方式は設定で選ぶ。

- **リング型** — 日付を囲む円の枠線が進捗バーになり、達成率で色が変わる（高い=成功色 / 中間=警告色 / 低い=危険色）。未来の日付は細い枠線のみ
- **塗り型** — 背景の塗りの濃さで達成率を表す。ベースカラーは「ランダム / 月ごと / 週ごとグラデーション」から選べる

**進捗バー**は、その期間に終わらせるべき範囲を1本のバーにしたもの。目盛り1つが1問に対応し、その問題の評価で色が変わる（◯=成功色、解/記=アクセント色、△=警告色、✕=危険色、未着手=枠のみ）。チャレンジも同じくバーで表示する。

日付をタップするとその日のTODOが出る。過去の日付なら、終わったか・どの評価だったかが分かる。

## タイマーの設計

経過時間は `setInterval` の加算ではなく、開始時刻（`Date.now()`）との差分から算出する。バックグラウンド遷移・画面スリープ・アプリの再起動をまたいでも正しい経過時間を保つ。

セッション状態は `SessionState` として IndexedDB に永続化され、アプリを閉じても計測中の状態が復元される。

## 評価の5択

| 値 | 記号 | ラベル |
|---|---|---|
| `perfect` | ◯ | 完璧にできた |
| `better_solution` | 解 | 正解だが、もっと簡単な解法があった |
| `weak_writing` | 記 | 正解だが、記述が甘い |
| `calc_error` | △ | 計算ミス |
| `wrong_approach` | ✕ | 方針が違った |

メモ欄・原因タグは設けない（原因は5択に内包される）。

## クラウド同期と MCP 連携（任意）

学習データを Cloudflare（Worker + KV）へ預けると、Claude などの MCP 対応AIから
学習状況を読み取り、今日のTODOや目標を変更できる。変更は次に同期したときPWAへ反映される。

```
study-todo（PWA・IndexedDB）
      ↓↑
Cloudflare Worker + KV  →  MCP Server  →  Claude などのAI
```

**この連携は追加機能**であり、設定しなければ今までどおりブラウザの中だけで動く。
サーバーが落ちていても、オフラインでも、学習の記録・タイマー・カレンダーはすべて使える。
オフライン中の記録は端末に貯まり、オンラインに戻ったときにまとめて送られる（何度送っても
`id` で重複しない）。

**AIは学習実績を作れない。** 公開しているのは「読む」ツールと「これからの予定・目標を
変える」ツールだけで、学習記録とチャレンジ結果を作れるのはPWA本体だけ。

| 種類 | 同期 |
|---|---|
| 学習記録・チャレンジ結果 | する（追加専用イベント。`id` で重複排除し、合計はサーバーで数え直す） |
| その日の予定（TaskPlan） | する（日付ごとに `revision` で競合を解く） |
| 目標 | する |
| 問題マスタ | する（指紋が変わったときだけ送る） |
| 計測中のタイマー・表示設定 | しない（端末ごとのもの） |
| 管理キー・端末キー・接続トークン | しない（端末の中だけ。バックアップJSONにも入らない） |

設定手順（Cloudflare の準備からClaudeへの登録まで）とツールの一覧は
**[docs/mcp.md](docs/mcp.md)** にある。

主なツール:
`getAppInfo` / `listQuestions` / `searchQuestions` / `getQuestion` / `getStudyHistory` /
`getRecentMistakes` / `getStudyStats` / `getRecentChallengeResult` / `getChallengeResults` /
`getTodayTasks` / `getTasksInRange` / `getGoals` / `getRecentAiChanges` /
`updateTodayTasks` / `updateTasksForDate` / `addGoal` / `updateGoal`

サーバー側のテストは `npm test`（Node標準のテストのみ。PWA本体は引き続きビルド不要）。

## 日付の扱い

「今日」は日本時間（UTC+9）で判断する（`src/datetime.js`）。ISO文字列の先頭10文字をそのまま
使うと、深夜〜朝に前日として扱われてしまうため、日付の判定はすべてこのモジュールを通す。
MCPのツールでは `timezoneOffsetMinutes` で別の時間帯も指定できる（既定は540）。

## 問題マスタ

`data/questions.json` は、数研出版「改訂版 チャート式基礎からの数学I+A（青チャート）」の
**管理用メタデータ**である。問題文と解答は含まない。

| | 数学I | 数学A | 計 |
|---|---|---|---|
| 例題（基本・重要・演習） | 194 | 158 | 352 |
| EXERCISES | 134 | 107 | 241 |
| 計 | 328 | 265 | 593 |

1問 = 「1回解いて1回評価する単位」。例題の (1)(2)(3) は同じ1問として扱う。

各例題は SELECT STUDY の3コース（基本定着170問 / 精選速習174問 / 実力錬成135問）を持つ。

### 出典

| 項目 | 出典 |
|---|---|
| 例題の章・節・番号・種類・タイトル・難易度・掲載ページ・コース | 数研出版が配布している例題一覧 Excel（`tools/source/examples.json`） |
| EXERCISES の番号・難易度・所属する節 | 誌面（`tools/source/exercises.json`） |

EXERCISES の難易度は誌面の小さな丸数字から読み取ったもので、抜き取り検証で
読み違いが見つかったため `needsReview: true` を付けてある。掲載ページは
例題一覧とは別の刷りのものなので持たせていない。

元データを直したら、次を実行して `data/questions.json` を作り直す（整合性チェックつき）。

```sh
npm run build:questions
```
